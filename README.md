# Tennis App

ML-пайплайн для детекции мяча в настольном теннисе и веб-приложение для разметки видео.

---

## Структура проекта

```
dataset/                    — исходные видео (.mov) по категориям
tennis-dataset/             — датасет с разметкой стола и ракеток (без мяча)
  images/Validation/        — 1386 кадров PNG 1280×720
  labels/Validation/        — YOLO seg полигоны (класс 1=стол, 2=сетка, 3=ракетка)
model/                      — архитектура 3D CNN и пайплайн обучения
webapp/                     — FastAPI + одностраничный аннотатор
  static/index.html         — SPA с двумя режимами разметки
  detector.py               — YOLO singleton для автодетекции мяча
  ball_storage.py           — хранилище ball-аннотаций
annotations/
  annotations.json          — разметка игровых событий (net/bounce/hit)
  ball_annotations.json     — разметка мяча (cx, cy, visibility, source)
yolo_det.pt                 — YOLO детекция (ball, table, grid, racket)
yolo_seg.pt                 — YOLO сегментация
```

## Запуск веб-аннотатора

```bash
uv sync
python main.py
# открыть http://127.0.0.1:8000
```

### Режим Events (игровые события)

| Клавиша | Действие |
|---|---|
| `←` / `→` | ±1 кадр |
| `Shift+←` / `Shift+→` | ±10 кадров |
| `N` | net |
| `B` | bounce |
| `H` | hit |
| клик по таймлайну | переход к кадру |

### Режим Ball (разметка мяча)

При загрузке каждого кадра автоматически запускается YOLO-детектор.

| Клавиша / действие | Результат |
|---|---|
| `Space` | принять YOLO-детекцию (source=yolo) |
| клик на кадр | поставить мяч вручную (source=manual) |
| `V` | пометить кадр как «мяч не виден» (visibility=0) |
| `Esc` | сбросить pending-детекцию |
| `←` / `→` | навигация по кадрам |

Если YOLO нашёл мяч — показывается жёлтый пунктирный bbox с уверенностью.
Принятые аннотации отображаются зелёным кружком на кадре и зелёными маркерами на таймлайне.
Кадры с visibility=0 — серые маркеры.

Аннотации хранятся в `annotations/ball_annotations.json`:
```json
{
  "videos": {
    "normal_point/1.mov": [
      {"frame_idx": 42, "cx": 1234.5, "cy": 678.0, "visibility": 1, "source": "yolo"},
      {"frame_idx": 100, "cx": 0, "cy": 0, "visibility": 0, "source": "manual"}
    ]
  }
}
```

## Адаптация TrackNet для детекции мяча

YOLO плохо справляется с быстрым маленьким мячом — видит каждый кадр независимо, теряет мяч при смазе и малом размере. [TrackNet](https://github.com/yastrebksv/TrackNet) решает это через 3-кадровый контекст и тепловые карты.

> **Важно:** `tennis-dataset` не содержит разметки мяча — только стол, сетка, ракетки. Разметку мяча нужно собирать через веб-аннотатор (режим Ball).

### Как работает TrackNet

- **Вход**: 3 последовательных кадра → 9-канальный тензор, ресайз до 640×360
- **Выход**: Gaussian heatmap → HoughCircles → координаты (x, y)
- **Разметка**: CSV с полями `frame, prev1, prev2, heatmap, x, y, visibility`
- **Архитектура**: энкодер-декодер (UNet-стиль), универсальная

### Пошаговый план

#### Шаг 1 — Разметить мяч через веб-аннотатор

Режим **Ball** в интерфейсе:
- YOLO автоматически предлагает позицию — `Space` чтобы принять
- Если не нашёл — кликнуть на кадр вручную
- `V` — мяч не виден в кадре

Цель: пройти все видео из `dataset/`, аннотировать каждый кадр.
Результат сохраняется в `annotations/ball_annotations.json`.

#### Шаг 2 — Извлечь кадры из видео

```
dataset/normal_point/1.mov  →  frames/normal_point_1/frame_000000.jpg
                                                      frame_000001.jpg
                                                      ...
```

`cv2.VideoCapture` → каждый кадр как JPG при 640×360. Имена с нулевым выравниванием.

#### Шаг 3 — Собрать CSV с разметкой

Конвертировать `ball_annotations.json` в формат TrackNet — одна строка на триплет кадров:

```
frame_path, prev1_path, prev2_path, heatmap_path, x, y, visibility
frames/clip1/frame_000002.jpg, .../000001.jpg, .../000000.jpg, heatmaps/clip1/000002.jpg, 412, 210, 1
```

- `visibility = 0` — мяч не виден
- Для кадров 0 и 1: дублировать первый кадр как prev1/prev2

#### Шаг 4 — Сгенерировать тепловые карты

Для каждого кадра с `visibility = 1`:
- Пустое изображение 360×640
- Gaussian-ядро 20×20 (σ=10) с центром в `(x * 640/orig_w, y * 360/orig_h)`
- Нормализовать: центр = 255, сохранить как JPG

Для `visibility = 0` — пустая (нулевая) карта.
Готовый скрипт: `gt_gen.py` из репозитория TrackNet.

#### Шаг 5 — Клонировать и адаптировать TrackNet

```bash
git clone https://github.com/yastrebksv/TrackNet
```

Что менять:
- `dataset.py` — пути до своих CSV / кадров / тепловых карт
- `model.py` — без изменений
- `main.py` — пути, batch size, количество эпох

#### Шаг 6 — Обучить

```bash
python main.py --batch_size 4 --epochs 100 \
  --train_csv labels_train.csv --val_csv labels_val.csv
```

Аугментации при небольшом датасете:
- Горизонтальное отражение (зеркалить и координату x)
- Яркость / контраст
- Небольшие случайные кропы (мяч должен остаться в кадре)

Метрика валидации — F1 с допуском 5 пикселей.

#### Шаг 7 — Интеграция

Заменить YOLO в `apply_to_frame.py`:

```
3 кадра → TrackNet → тепловая карта → HoughCircles → (x, y) или None
```

### Почему TrackNet лучше YOLO для мяча

| | YOLO | TrackNet |
|---|---|---|
| Контекст | 1 кадр | 3 кадра (видит движение) |
| Малый размер мяча | плохо | хорошо (тепловая карта) |
| Смаз при быстром движении | теряет | обрабатывает |
| Окклюзия | теряет | может предсказать по траектории |
| Минимум данных для старта | много | ~500 кадров |
